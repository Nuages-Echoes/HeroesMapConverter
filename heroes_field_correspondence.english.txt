Values used in the unified JSON format and their equivalents in .fh2m and .h3m
   ╔╦╦╦════════════════════════════════════════════════════════════════════╦╦╦╗
   ║║║║  Unified JSON / FH2M / H3M value correspondences                   ║║║║
   ╚╩╩╩════════════════════════════════════════════════════════════════════╩╩╩╝

   Each table below lists the concrete values of one field in the three
   formats: the value as it appears in the unified JSON files
   (outputunified/), its equivalent in the .fh2m files (as parsed by
   h2decoder.py / stored by the fheroes2 engine), and its equivalent in
   the .h3m files (as parsed by h3decoder.py). UNDEFINE means the value
   has no direct or obvious equivalent in that format.

   FH2M values marked with an enum come from the fheroes2 source code;
   the number in parentheses is the raw value stored in the file.

██ Player colors                                                          ██
████████████══════════════════════════════════════════████████████████

| JSON unified | FH2M                                       | H3M          |
|--------------|--------------------------------------------|--------------|
| "Blue"       | PlayerColor::BLUE (bit 0x01)               | "Blue"       |
| "Green"      | PlayerColor::GREEN (bit 0x02)              | "Green"      |
| "Red"        | PlayerColor::RED (bit 0x04)                | "Red"        |
| "Yellow"     | PlayerColor::YELLOW (bit 0x08)             | "Tan"        |
| "Orange"     | PlayerColor::ORANGE (bit 0x10)             | "Orange"     |
| "Purple"     | PlayerColor::PURPLE (bit 0x20)             | "Purple"     |
| "Tan"        | UNDEFINE (no such color in H2)             | "Tan"        |
| "Teal"       | UNDEFINE                                   | "Teal"       |
| "Pink"       | UNDEFINE                                   | "Pink"       |

   In FH2M, sets of colors (availablePlayerColors, humanPlayerColors,
   computerPlayerColors, alliances[]) are stored as bit masks combining
   the values above. In H3M, each of the 8 players carries its color
   name and two booleans (Human Playable / AI Playable).

██ Starting heroes (playerDetails[].hasStartingHero)                     ██
████████████████████████████████████████████████████████████████████

| JSON unified                        | FH2M                                | H3M                                   |
|-------------------------------------|-------------------------------------|---------------------------------------|
| playerDetails[].hasStartingHero:    | tiles[].objects with group          | Player Heroes > Has Random Hero      |
| true                                | "KINGDOM_HEROES": the starting      | / Hero Type                          |
|                                     | hero is a hero object placed on     |                                       |
|                                     | a tile                              |                                       |
| playerDetails[].race (of a hero):   | object index = color * 7 + race:     | Player Heroes > Hero Type            |
| "Knight"                            | metadata[0] = color (0-5),           | (00-7F, FF = no hero)                |
|                                     | metadata[1] = race (0-6)             |                                       |

   The FH2M format has no explicit starting hero field: a player has a
   starting hero if and only if a KINGDOM_HEROES object of his color is
   placed on the map. The conversion creates one object per available
   player (placed near the main town when it exists) and back-extracts
   hasStartingHero and the hero race from the object index.

██ Objects (placed on the map)                                          ██
████████████████████████████══════════════════════════════████████████

   The unified format stores placed objects the fh2m way: per tile
   (key "x_y_z") with metadata maps keyed by object id.

| JSON unified                          | FH2M                        | H3M                                        |
|---------------------------------------|-----------------------------|--------------------------------------------|
| objects.tiles["x_y_z"][]               | tiles[].objects (objects    | Objects > Tiles > tiles (decoded           |
|   .id / .group / .index               |   are on their tile in      |   instances, stored per tile)              |
|                                       |   the tile list)            |   .group mapped from the OBJECTS.TXT       |
|                                       |                             |   class via H3M_CLASS_TO_GROUP             |
| objects.monsterMetadata[id]           | monsterMetadata             | Objects > Tiles > monsterMetadata           |
|   (count, creature)                   |   (count, joinCondition,   |   (count, creature)                        |
|                                       |    selected)                |                                            |
| objects.resourceMetadata[id]          | resourceMetadata (count)    | Objects > Tiles > resourceMetadata          |
|   (count, resource)                   |                             |   (count, resource)                        |
| objects.artifactMetadata[id]          | artifactMetadata (radius,   | Objects > Tiles > artifactMetadata          |
|   (artifact, spell for scrolls)       |   captureCondition,        |   (artifact; spell for spell scrolls)      |
|                                       |   selected)                 |                                            |
| objects.signMetadata[id] (message)    | signMetadata (message)      | Objects > Tiles > signMetadata (message)   |
| objects.ownableMetadata[id] (owner)   | capturableObjectsMetadata   | Objects > Tiles > ownableMetadata (owner   |
|                                       |   (ownerColor)              |   of mines and dwellings)                  |
| objects.townMetadata[id] (owner,     | castleMetadata (customName, | Objects > Tiles > townMetadata (owner,      |
|   customName, type)                   |   garrison, buildings,     |   customName, type)                        |
|                                       |   spells, hiring)           |                                            |
| objects.heroMetadata[id]              | heroMetadata (full hero     | Objects > Tiles > heroMetadata (owner,      |
|   (owner, type)                       |   customization)            |   type)                                    |
| objects.eventMetadata[id] (message)   | adventureMapEventMetadata  | Objects > Tiles > eventMetadata            |
|                                       |   (message, rewards...)    |   (message)                                |
| objects.shrineMetadata[id] (spell)    | UNDEFINE (no shrines in     | Objects > Tiles > shrineMetadata (spell)    |
|                                       |   the fh2m object set)      |                                            |
| objects.castleMetadata /              | castleMetadata              | UNDEFINE (town metadata is stored in       |
|   sphinxMetadata /                    | sphinxMetadata              |   townMetadata, differently structured)    |
|   adventureMapEventMetadata /         | adventureMapEventMetadata   |                                            |
|   selectionObjectMetadata /           | selectionObjectMetadata     |                                            |
|   capturableObjectsMetadata           | capturableObjectsMetadata   |                                            |
| objects.dropped[] (ids of objects     | UNDEFINE                    | Objects whose OBJECTS.TXT class has no     |
|   whose class has no unified group)   |                             |   unified group mapping                    |

   Note: h3m "UNDEFINED_*" classes are mostly landscape/decoration
   objects (trees, rocks, mountains...) which have no gameplay data and
   no fh2m object equivalent; they are dropped and their ids are listed
   in objects.dropped.

██ Values not converted to the unified format                             ██
████████████══════════════════════════════════════════████████████████

List for FH2M (no unified equivalent yet):
- isCampaign (campaign maps have a different structure)
- additionalInfo (campaign maps only)
- tiles[].terrainFlags (image mirroring flags)
- tiles[].objects joinCondition / isWeeklyGrowthDisabled / selected
  (the object placement itself is converted)
- castleMetadata garrison, buildings, spells, hiring (owner, name and
  type are converted)
- heroMetadata portraits, armies, artifacts, spells, patrol, skills,
  experience, primary skills, mana (owner and type are converted)
- sphinxMetadata riddles, answers, rewards (placement is converted)
- signMetadata (message is converted)
- adventureMapEventMetadata rewards, skills, monsters (message is
  converted)
- selectionObjectMetadata selected items (placement is converted)
- capturableObjectsMetadata details beyond the owner color
- monsterMetadata joinCondition, isWeeklyGrowthDisabled, selected
- artifactMetadata radius, captureCondition, selected
- resourceMetadata (count and type are converted)
- standardObjectMetadata (deprecated, pre-v10)
- translations (translated name/description/creatorNotes)
- translationInfo (all translated texts)

List for H3M (no unified equivalent yet):
- Basic Parameters > Has Hero
- Basic Parameters > Heroes Mastery Level Cap
- Players Attributes > Behavior (0-Random, 1-Warrior, 2-Builder,
  3-Explorer)
- Players Attributes > Owned Towns (detailed per-town ownership)
- Players Attributes > Owns Random Town
- Player Heroes > Hero Face and Hero Name (converted heroes carry the
  default face and name; Has Random Hero / Hero Type are converted)
- Available Heroes > Bitfield
- Random Artifacts > Bitfield
- Allowed Spells > Bitfield
- Allowed Abilities > Bitfield
- Reserved Bytes
- Hero Settings (predefined hero settings, skipped by h3decoder.py)
- Objects > Raw Data (the object instances are decoded into
  Objects > Tiles and mapped to the unified format; the raw bytes are
  kept for reference)
- Victory/Loss condition details (allow normal victory, applies to AI,
  condition metadata: coordinates, artifact/creature codes, amounts)
- Surface/Underground Map > Grid > Terrain Picture
- Surface/Underground Map > Grid > River Type / River Properties
- Surface/Underground Map > Grid > Road Type / Road Properties
- Surface/Underground Map > Grid > Mirroring
