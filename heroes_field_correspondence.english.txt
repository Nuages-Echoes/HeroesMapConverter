   Each table below lists the concrete values of one field in the three
   formats: the value as it appears in the unified JSON files
   (outputunified/), its equivalent in the .fh2m files (as parsed by
   h2decoder.py / stored by the fheroes2 engine), and its equivalent in
   the .h3m files (as parsed by h3decoder.py). UNDEFINE means the value
   has no direct or obvious equivalent in that format.

   FH2M values marked with an enum come from the fheroes2 source code;
   the number in parentheses is the raw value stored in the file.

List for FH2M (no unified equivalent yet):
- isCampaign (campaign maps have a different structure)
- additionalInfo (campaign maps only)
- standardObjectMetadata (deprecated, map versions below 10 only)

The fh2m translations are carried into the unified format:
- translations: the translated base map texts (name, description,
  creatorNotes) per language, at the unified root under
  "translations" (map format versions 11+)
- translationInfo: all the translated gameplay texts (daily events,
  rumors, and the texts of the castle, hero, sphinx, sign and event
  metadata), under objects.translationInfo (map format versions 11+)

The fh2m metadata maps are fully carried into the unified format:
every entry keeps its raw fh2m fields (for the byte-perfect fh2m
round-trip) and gains normalized fields with readable names resolved
from the identifier tables in correspondence.py:
- castleMetadata defenders[] (monster, sourceMonsterId, count),
  builtBuildingNames / bannedBuildingNames (building bit flags),
  mustHaveSpellNames / bannedSpellNames (spells)
- heroMetadata army[] (monster, sourceMonsterId, count),
  artifactNames, availableSpellNames, secondarySkills[] (skill,
  sourceSkillId, level, sourceLevelId), primarySkills (attack,
  defense, knowledge, spellPower), raceName (race bit flags),
  portraitName (portrait:<id>, None for the default portrait),
  patrol (enabled, radius), progression (level, experience, mana;
  None keeps the game defaults)
- castleMetadata raceName (from the KINGDOM_TOWNS object index) and
  availableToHire[] (monster per dwelling tier 1-6, count; -1 keeps
  the game default growth)
- sphinxMetadata artifactName, artifactMetadataName (spell of the
  Spell Scroll reward, when the artifact is a Spell Scroll)
- adventureMapEventMetadata artifactName, artifactMetadataName (Spell
  Scroll spell), secondarySkillName, secondarySkillLevelName,
  monsterName, primarySkillBonus (attack, defense, knowledge,
  spellPower)
- monsterMetadata joinConditionName
- artifactMetadata selectedNames (artifacts or spells of the random
  artifact / Spell Scroll selections)
- selectionObjectMetadata selectedItemNames: the items of the choice
  objects, typed by the placed object (Witch's Hut -> secondary
  skills, Pyramid -> level 5 spells)
The remaining raw fh2m fields have no readable-name equivalent yet
(capturable owner beyond the color, artifact radius/captureCondition).

List for H3M (no unified equivalent yet):
- Basic Parameters > Heroes Mastery Level Cap
- Players Attributes > Behavior (0-Random, 1-Warrior, 2-Builder,
  3-Explorer)
- Reserved Bytes

The h3m metadata maps are carried into the unified format with
normalized names resolved from the correspondence tables (the raw
values stay for the h3m round-trip, which goes through the raw
object section bytes):
- townMetadata ownerName, garrisonNamed[] (creature names)
- garrisonMetadata ownerName, creaturesNamed[]
- heroMetadata typeName, ownerName, skillsNamed[]
- shrineMetadata spellName
- witchhutMetadata skillName
- scholarMetadata rewardTypeName
- seerMetadata questArtifactName, quest artifactNames[],
  reward artifactName / spellName / creatureName
- eventMetadata artifactName
The remaining h3m fields stay raw (building and spell bitfields,
quest messages, garrison canTake, event players flags).


   Town/race conversion (h3m -> fh2m): the h3m town types map to
   the Heroes II races through the faction pairings, and the fh2m
   KINGDOM_TOWNS object index is race * 2 (castle) or race * 2 + 1
   (town), the fheroes2 race order being Knight, Barbarian,
   Sorceress, Warlock, Wizard, Necromancer:

| H3M type | H3M faction | FH2M race | FH2M index (castle) |
|----------|-------------|-----------|---------------------|
| 0        | Castle      | Knight    | 0                   |
| 1        | Rampart     | Sorceress | 4                  |
| 2        | Tower       | Wizard    | 8                   |
| 3        | Inferno     | Warlock   | 6                   |
| 4        | Necropolis  | Necromancer | 10              |
| 5        | Dungeon     | Warlock   | 6                   |
| 6        | Stronghold  | Barbarian | 2                   |
| 7        | Fortress    | Barbarian | 2                   |
| 8        | Conflux     | Sorceress | 4                   |
| random   | -           | Knight (default) | 0         |

   The garrison creatures of an h3m town become the fh2m castle
   defenders (the first five non-empty slots, converted through the
   creature table).

   Shrine conversion (h3m -> fh2m): the Heroes III shrines convert to
   the Heroes II shrine circles (ADVENTURE_POWER_UPS group):

| H3M class | H3M shrine                | FH2M index | FH2M shrine              |
|-----------|---------------------------|------------|--------------------------|
| 88        | Shrine of Magic Incantation | 14       | Shrine of the First Circle |
| 89        | Shrine of Magic Gesture    | 15        | Shrine of the Second Circle |
| 90        | Shrine of Magic Thought   | 16        | Shrine of the Third Circle |

   The Heroes II Shrine of Magic Mystery has no Heroes III
   equivalent: it converts to the Third Circle (h3m class 90). A
   definite h3m shrine spell converts through the spell table when
   an equivalent exists; a random h3m spell (0xFF) stays random.

   Rumors (fh2m -> h3m): the Heroes II rumors carry no name; the
   h3m rumors need one, so the conversion generates RumeurX names
   (Rumeur1, Rumeur2...) with X incremented per unnamed rumor. The
   rumors that already carry a name (from an h3m source) keep it.

   Landscape variants (fh2m -> h3m): the Heroes II landscape
   groups carry more entries than the literal ObjectInfo count of
   map_object_info.cpp (the populate functions generate variants
   through loops): LANDSCAPE_MOUNTAINS holds 8 terrains x 19
   variants (indexes 0-151), LANDSCAPE_ROCKS 40, LANDSCAPE_TREES
   53, LANDSCAPE_MISCELLANEOUS 147, LANDSCAPE_TOWN_BASEMENTS 8
   (one per terrain) and LANDSCAPE_FLAGS 14 (7 colors x 2
   sides). The FH2M_LANDSCAPE_TO_H3M table now covers them all.
   The mountains pick their h3m class from the terrain of the
   tile (the fh2m variant index formula being undocumented):
   Lava -> volcano (158), Desert/Sand -> dune (148), Dirt ->
   mound (133), the others -> mountain (134); the extra rocks
   map to rocks (147), the extra tree variants (29-62) to the h3m
   tree classes - the encoder refines by tile terrain (Swamp and
   Dirt -> dead vegetation 119, the other terrains -> trees 155)
   - and the loop-generated misc variants (116-146) to cracks
   (118). The flags, the town basements and the Barrel
   (ADVENTURE_WATER 12, an fheroes2-specific object with no h3m
   counterpart) stay dropped: the h3m towns carry their own
   basements and flags.

   Power-up pairings (per user decision, fh2m -> h3m): the
   Heroes II power-ups map to their h3m counterparts - Artesian
   Spring -> Magic Spring (48), Watering Hole -> Watering Hole
   (110), Faerie Ring (the 3 variants) -> Faerie Ring (28), Oasis
   -> Oasis (56), Fountain -> Fountain of Fortune (30), Fort ->
   Marletto Tower (23), Witch Doctor's Hut -> Garden of
   Revelation (32), Mercenary Camp -> Mercenary Camp (51),
   Standing Stones -> Star Axis (61), Temple -> Temple (96),
   Xanadu -> Library of Enlightenment (41), Arena -> Arena (4);
   the Genie's Lamp -> Refugee Camp (78). The Oasis sprite
   (AVXosis0.def) is added to the reference catalog.

   Obelisks (both directions): the Heroes II obelisks (the 7
   terrain variants, ADVENTURE_MISCELLANEOUS 9-15) encode to the
   h3m obelisk (class 57) - the puzzle-map mechanic exists in
   both games; the h3m obelisk converts back to the generic
   Heroes II obelisk (MISC 15). The FH2M_TO_H3M_MISC keys are
   now prefixed MISC_<index> (as the WATER_ keys) so the
   ADVENTURE_MISCELLANEOUS indexes cannot collide with the
   ADVENTURE_TREASURES indexes (the campfires 8-9 stay on the
   treasure keys).

   Gazebo (fh2m -> h3m): the Heroes II Gazebo (ADVENTURE_POWER_UPS
   11) encodes to the h3m learning stone (class 100), the inverse
   of the H3M_TO_FH2M_INTERACTIVE pairing. The creature sprite
   catalog also extends to the AVW convention for the paired
   creatures without a test-map sprite (avwpike Pikeman, avwhcrs

   Tile writer (fh2m -> h3m): the fh2m terrain image index (the
   raw sourceTerrain 'terrain:<index>') becomes the h3m Terrain
   Picture: the position within the fh2m terrain image range, modulo
   the about 72 h3m per-terrain image variants, gives a valid and
   visually varied h3m picture. The fh2m ROADS and STREAMS objects
   convert back to the h3m per-tile Road Type (Dirt) and River Type
   (Clear) fields. The h3m road/river variants (the per-tile
   properties) are not carried back (the h3m engine recomputes the
   connections from the neighbors).

   Header bitfields (h3m -> unified): the available heroes bitfield
   is decoded - a cleared bit means the hero cannot be hired (e.g.
   Verdish, id 123, blocked in the 'all for one' prison) and is
   transported as unavailableHeroes with the hero id and name; the
   raw bitfield stays for the round-trip. The player AI behaviors
   (Random, Warrior, Builder, Explorer) are transported as
   playerBehaviors; the custom starting heroes (Hero Type with the
   hero name) as customStartingHeroes; the AB+ random artifacts and
   the SoD allowed spells/abilities bitfields are transported raw
   (randomArtifactsBitfield, allowedSpellsBitfield,
   allowedAbilitiesBitfield). None of these has a Heroes II
   equivalent: the Heroes II editor does not restrict heroes,
   spells or artifacts.

   Decorative objects (h3m -> fh2m): the decorative h3m classes
   (identified by the sprite families: AVLsh shrubs, AVLmt
   mountains, AVLf flowers, AVLca cacti, AVLtr trees, AVLr rocks,
   AVLdead dead trees, AVLlav lava lakes, AVLms mosses and so on)
   convert to representative Heroes II landscape objects through
   the H3M_DECORATIVE_TO_FH2M table (a shrub becomes a grass shrub,
   a mountain a medium mountain, a cactus a desert cactus, a dead
   tree a generic dead tree...). The classes without a mapping stay
   dropped. The UNDEFINED_<class> objects stay in the unified JSON
   so future mappings can extend the coverage.

   Roads and rivers (h3m -> fh2m): the h3m format stores the road
   and river types per tile (Dirt/Gravel/Cobblestone roads,
   Clear/Icy/Muddy/Lava rivers); the Heroes II format places a ROADS
   or STREAMS object per tile whose index is the connection bitfield
   (TOP_LEFT=1, TOP=2, TOP_RIGHT=4, RIGHT=8, BOTTOM_RIGHT=16,
   BOTTOM=32, BOTTOM_LEFT=64, LEFT=128). The connections are derived
   from the neighboring tiles carrying a road/river. The road and
   river variants and the type distinction (all the h3m road types
   become the single Heroes II road, all the river types the single
   stream) are not carried.

   Conversion guards (h3m -> fh2m, unified_to_fh2m): a map with an
   underground raises 'Heroes of Might and Magic 2 ne permet pas de
   jouer avec le sous-sol, la carte X ne peut pas être convertie';
   a map with more than 6 available players raises 'Le nombre de
   factions est limité à 6 dans H2, impossible de convertir la carte
   X'.

   Cross-format object translation (h3m -> fh2m, main.py --target fh2m):
   placed objects are translated group by group when an fh2m
   equivalent exists; the others are dropped and their ids are listed
   under objects.dropped. The identifier pairs (creatures, artifacts,
   spells, resources) come from the tables in correspondence.py:
   - MONSTERS: h3m creature -> fh2m monster (index = monster id - 1),
     with the count, the after-defeat message and resources when
     present; creatures with no Heroes II equivalent are dropped
   - ADVENTURE_TREASURES: h3m resource -> fh2m resource object index
     (0 wood ... 6 gold)
   - ADVENTURE_ARTIFACTS: h3m artifact -> fh2m artifact (index follows
     the fheroes2 ADVENTURE_ARTIFACTS group order); random h3m
     artifacts become fh2m random artifacts; artifacts with no Heroes
     II equivalent are dropped
   - KINGDOM_HEROES: h3m hero -> fh2m hero object (index = color * 7 +
     race from the hero pairing) with a full heroMetadata: name,
     experience, primary skills, secondary skills (converted through
     the secondary skill table; the skills with no Heroes II
     equivalent become the random skill, keeping their level), army
     (the first five non-empty
     creature slots), artifacts (worn slots and backpack through the
     artifact table), available spells (bitfield through the spell
     table) and patrol state; neutral heroes (owner 255) are dropped;
     biography, face and gender have no Heroes II equivalent
   - ADVENTURE_MINES / ADVENTURE_DWELLINGS: translated with a
     capturableObjectsMetadata carrying the owner color (when the
     owner is a Heroes II color)
   - KINGDOM_TOWNS: translated with the fh2m race from the h3m town
     type (see the town/race table above) and a castleMetadata
     carrying the custom name, the garrison creatures as defenders
     and the built/disabled buildings converted to the fh2m building
     flags (castle, tavern, marketplace, shipyard, mage guild 1-5
     and the generic dwellings with their upgrades; town halls, fort
     and citadel have no Heroes II equivalent)
   - ADVENTURE_POWER_UPS: shrines are translated to the matching
     shrine circle (Incantation -> First Circle, Gesture -> Second
     Circle, Thought -> Third Circle); other power-up objects are
     dropped
   - ADVENTURE_MISCELLANEOUS: pandora boxes (h3m class 21 group)
     convert to the fh2m Sphinx object (index 31) like the seer
     huts: the guard message becomes the riddle (a default riddle
     when there is no guard), the answers stay empty and the
     artifact or resource bonuses convert; the other h3m bonuses
     (experience, mana, morale, luck, primary and secondary skills,
     spells, creatures) and the guard fight are lost. Seer huts
     (h3m class 62 group) convert to the fh2m Sphinx object
     (index 31): the riddle is the fixed 'Validez pour obtenir la
     recompense.' prompt with an empty valid answer. The reward
     converts when the fh2m sphinx supports it (an artifact or
     resources); the other h3m reward types (experience, morale,
     luck, primary and secondary skills, spells, creatures) are
     lost. A seer with no quest is dropped. Witch huts (h3m class
     113) and scholars
     (h3m class 62) convert to the fh2m Witch's Hut object (index 26);
     the fh2m format carries no per-hut metadata, the engine draws
     the secondary skill at game start (the h3m fixed skill and the
     scholar reward are lost). Garrisons (h3m class 35) convert to a
     monster troop: the highest level creature (the highest h3m
     creature id among the non-empty slots) becomes a placed monster
     with its count; a garrison with no creature, or whose best
     creature has no Heroes II equivalent, is dropped. Ground events
     (h3m class 26) convert to
     the fh2m event object (index 38) with a full
     adventureMapEventMetadata: message, player colors (the h3m
     player bitmask maps to the Heroes II colors; an empty mask means
     every player), resources, primary skills, experience, the first
     secondary skill (through the secondary skill table, the skills
     with no equivalent becoming the random skill), the first
     artifact (the Spell Scroll carrying its spell through the spell
     table) and the first creature; removeAfterVisit inverts into
     isRecurringEvent. Signs are translated with their message
   The remaining h3m groups (pandora boxes, shrines, seer huts, garrisons...)
   have no fh2m equivalent and are dropped. fh2m object groups that are
   pure landscape (ROADS, STREAMS, LANDSCAPE_*) exist only on the fh2m
   side.
