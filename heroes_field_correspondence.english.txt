Values used in the unified JSON format and their equivalents in .fh2m and .h3m
   ╔╦╦╦════════════════════════════════════════════════════════════════════╦╦╦╗
   ║║║║  Unified JSON / FH2M / H3M value correspondences                   ║║║║
   ╚╩╩╩════════════════════════════════════════════════════════════════════╩╩╩╝

   Each table below lists the concrete values of one field in the three
   formats: the value as it appears in the unified JSON files
   (outputunified/), its equivalent in the .fh2m files (as parsed by
   h2decoder.py / stored by the fheroes2 engine), and its equivalent in
   the .h3m files (as parsed by h3decoder.py). UNDEFINE means the value
   has no direct or obvious equivalent in that format.

   FH2M values marked with an enum come from the fheroes2 source code;
   the number in parentheses is the raw value stored in the file.

██ Player colors                                                          ██
████████████══════════════════════════════════════════████████████████

| JSON unified | FH2M                                       | H3M          |
|--------------|--------------------------------------------|--------------|
| "Blue"       | PlayerColor::BLUE (bit 0x01)               | "Blue"       |
| "Green"      | PlayerColor::GREEN (bit 0x02)              | "Green"      |
| "Red"        | PlayerColor::RED (bit 0x04)                | "Red"        |
| "Yellow"     | PlayerColor::YELLOW (bit 0x08)             | "Tan"        |
| "Orange"     | PlayerColor::ORANGE (bit 0x10)             | "Orange"     |
| "Purple"     | PlayerColor::PURPLE (bit 0x20)             | "Purple"     |
| "Tan"        | UNDEFINE (no such color in H2)             | "Tan"        |
| "Teal"       | UNDEFINE                                   | "Teal"       |
| "Pink"       | UNDEFINE                                   | "Pink"       |

   In FH2M, sets of colors (availablePlayerColors, humanPlayerColors,
   computerPlayerColors, alliances[]) are stored as bit masks combining
   the values above. In H3M, each of the 8 players carries its color
   name and two booleans (Human Playable / AI Playable).

██ Rumors and booleans                                                   ██
████████████══════════════════════════════════████████████████████████

| JSON unified        | FH2M                       | H3M                |
|---------------------|----------------------------|--------------------|
| rumors[].text:      | rumors: the message text   | Rumors > Text      |
| "some text"         | (UTF-8 string)             | (string)           |
| rumors[].name:      | UNDEFINE (rumors have no   | Rumors > Name      |
| "some name" / null  | name)                      | (string)           |
| isCampaign-like     | UNDEFINE (out of scope of the unified format,       |
| flags               | see the two lists below)   |                    |

   Booleans are stored as true/false in JSON, 1/0 (uint8) in both
   FH2M and H3M files: hasUnderground (H3M only: 0-Single-level,
   1-Two-level), players' Human/AI Playable, etc.

██ Values not converted to the unified format                             ██
████████████══════════════════════════════════════════████████████████

List for FH2M (no unified equivalent yet):
- isCampaign (campaign maps have a different structure)
- additionalInfo (campaign maps only)
- tiles[].terrainFlags (image mirroring flags)
- tiles[].objects (placed objects: id, group, index)
- castleMetadata (custom names, garrison, buildings, spells, hiring)
- heroMetadata (names, portraits, armies, artifacts, spells, patrol,
  skills, experience, primary skills, mana, race)
- sphinxMetadata (riddles, answers, rewards)
- signMetadata (sign messages)
- adventureMapEventMetadata (messages, rewards, skills, monsters)
- selectionObjectMetadata (selected items)
- capturableObjectsMetadata (owner colors of capturable objects)
- monsterMetadata (counts, join conditions, random monster selections)
- artifactMetadata (radii, scroll spells, random artifact selections)
- resourceMetadata (resource counts)
- standardObjectMetadata (deprecated, pre-v10)
- translations (translated name/description/creatorNotes)
- translationInfo (all translated texts)

List for H3M (no unified equivalent yet):
- Basic Parameters > Has Hero
- Basic Parameters > Heroes Mastery Level Cap
- Players Attributes > Behavior (0-Random, 1-Warrior, 2-Builder,
  3-Explorer)
- Players Attributes > Owned Towns (detailed per-town ownership)
- Players Attributes > Owns Random Town
- Player Heroes (starting heroes: random hero, type, face, name,
  number of heroes)
- Available Heroes > Bitfield
- Random Artifacts > Bitfield
- Allowed Spells > Bitfield
- Allowed Abilities > Bitfield
- Reserved Bytes
- Hero Settings (predefined hero settings, skipped by h3decoder.py)
- Objects (Raw Data: object entries are not decoded)
- Victory/Loss condition details (allow normal victory, applies to AI,
  condition metadata: coordinates, artifact/creature codes, amounts)
- Surface/Underground Map > Grid > Terrain Picture
- Surface/Underground Map > Grid > River Type / River Properties
- Surface/Underground Map > Grid > Road Type / Road Properties
- Surface/Underground Map > Grid > Mirroring
