4. Lossy-by-design collapses (converted, but not 1:1)
------------------------------------------------------------

  - Scenery sprite variants -> one OE sid per family/biome
    (e.g. all pine variants -> pinetree_1 / pinetree_snow_1); the way back
    recovers the family, not the exact variant.
  - Specific H3 artifacts -> OE random-item (see 3a); random artifact
    classes 65-69 -> random-item + rarity row.
  - Fixed and random monsters -> OE random-squad with a propSquads /
    propRandomSquads row (unit sids + tier kept; H3 quantity split lost).
  - Towns and heroes -> OE city-spawner / hero-spawner: the H2 town race /
    hero class is not kept per object.
  - Roads and rivers are not OE objects: they live in the terrain layer
    (roadsMap bitfield, rivers node lists).
  - H3 Event / Sign / Seer Hut / Quest Guard -> OE quest script triggers
    when the metadata fits: message -> Print, resources -> GiveRes,
    artifact -> GiveItemHero, skill -> AddSkillAll/AddSkillHero.
    Monster rewards, stat bonuses and unmatched artifact/skill ids are
    kept only in the trigger's comment field.
  - Den of Thieves AND Cover of Darkness both -> insaras_eye;
    Refugee Camp / Freelancers Guild / Mercenary Camp -> mercenary_guild.
  - OE _upg vs _upg_alt: both reverse to the same H3 creature id; forward
    (H3 -> OE) picks one at random, so .map output is non-deterministic
    for upgraded units.
  - Player colors: OE colorId is -1 in all real maps, so the color is
    assigned from the spawn order (first 6 = H2 order); the real color
    table lives in Core.zip and is not extracted yet.

5. Structural / container-level gaps
------------------------------------------------------------

  - headerHash is written as "0"*32 (the game's hash algorithm is unknown).
  - hommoe -> unified still drops: scenario/adventure "settings" (except
    mapWinConditions), customAreasPainting (~27.6 KB in Broken_Alliance),
    descBlocks, views, spawn flags (isAlive/isLocked/playerId/
    isCityDefined), takenHeroes, orphan objectsProperties rows, and the
    container header fields (gzipHeader/headerHash/separator/trailingData).
    Blocks 3/4 ARE carried raw in the unified "scripts" section.
  - unified -> .map regenerates only the H2/H3 event patterns; OE-native
    script features (counters, SetQuestMarker, NodeRevealed, interruptions,
    aiRolesId, dialogs) are parsed hommoe -> unified raw but are not
    regenerated from unified yet.
  - hommoe -> fh2m uses an anchor-shift heuristic for object coordinates.
  - Sidecar .json: passthrough byte-identical when the input .map has one;
    generated only when it carries meaningful data.
  - Known doc/data inconsistency still open: Faction 9 (Conflux) creature
    cells in heroes_field_correspondence.english.txt and h3 ids 112-125 in
    oe_object_correspondence.json still carry the reference's scrambled
    values (only Factions 2/4/8 were corrected).

6. Creature banks - evidence pack for the upcoming conversion
------------------------------------------------------------

H3 side (h3decoder.py + h3_names in oe_object_correspondence.json):
  - bank classes: 6 Pandora Box, 16 Creature Bank (subtype = bank type),
    25 Dragon Utopia, 84 Crypt, 146 Misc Active (water; creature banks).
    Classes 24 Derelict Ship / 85 Shipwreck also route to the fh2m
    ADVENTURE_DWELLINGS group but are water-travel -> DROPPED (section 0).
    h3decoder maps classes 16/24/25/84/85 -> fh2m group ADVENTURE_DWELLINGS.
  - per-instance payload in h3m: the "Guarded" structure = a message +
    an optional 7-slot monster guard stack (+4 trailing bytes);
    Pandora's Box additionally carries pandoraMetadata. The REWARD is
    defined by the bank type (class+subclass), not stored per instance.
  - H2 has no creature banks (fh2m ADVENTURE_DWELLINGS are plain dwellings).
